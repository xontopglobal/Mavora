## Migration and database safety

The remote development project records 13 migrations. This checkout contains six migration source files. Seven remote migration sources (including backend security, billing lifecycle, private helper permissions, and group API permission history) have no local counterpart; three local profile/avatar/business files also use version strings different from the remote ledger. The shared Circles version `20261123113205` matches. This is a migration-source reconciliation blocker for new schema changes. No migration, SQL mutation, storage mutation, or database write was run during this review.

The development project has three media buckets: private `avatars` (5 MiB image allowlist), public `mavora-media` (50 MiB image/video allowlist), and private `mavora-private-media` (50 MiB image/video allowlist). The private media policies currently restrict object access to the owner's folder. These facts are insufficient for safe follower-only post/story/reel media delivery.

The Supabase security advisor also reports 10 `SECURITY DEFINER` functions executable by authenticated users and two RLS-enabled tables without policies (`billing_event_log` and `role_permissions`). These are outside the front-end changes and were not altered; the privileged functions should be reviewed as part of the migration reconciliation and staff-security review.

## Recommended implementation order

1. Reconcile remote/local migration sources, then complete the pending eligibility review through an authorized verification workflow and test text publishing with an eligible account.
2. Review and sequence the narrowly scoped `is_private` self-update grant; test public/private profile reads, follow requests, and post visibility with separate accounts.
3. Design audience-authorized media reads and retention before implementing photo uploads and post playback.
4. Add Stories lifecycle/expiration, then Reels metadata and video playback on the reviewed media foundation.
5. Add atomic, authorized conversation creation and inbox/realtime behavior; verify with two accounts, blocks, and private profiles.
6. Connect membership catalog and checkout to a server-owned provider workflow, including webhook verification, idempotency, cancellations, and entitlements. Improve suggestion ranking after privacy and eligibility behavior is confirmed.

## Readability changes

Updated the existing shared `.ofsocio-app` palette and typography tokens in `social.css`, rather than keeping a separate readability override sheet. The dark surfaces, text, muted text, borders, and accents now use a brighter contrast palette; a shared 13px minimum applies to the app's small fixed text while heading sizes and hierarchy remain distinct. Disabled controls, navigation, helper/status copy, focus indicators, buttons, and mobile tap targets were improved. The styles remain responsive and honor reduced-motion preferences. The screenshots were used for visual direction; pixel-perfect comparison against the photographed display was not possible.
